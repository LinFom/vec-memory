# QQ-Agent 适配器

将本目录插件源码安装到 QQ-Agent 的 `plugins/memory-vec/`，使用该宿主的插件安装和启用方式。

先在独立服务中创建项目和空间，配置插件：

```json
{
  "protocolV1": true,
  "serviceBaseURL": "http://127.0.0.1:8091",
  "spaceId": "your-space",
  "serviceToken": "your-project-token"
}
```

默认 `protocolV1:false` 保留旧接入行为。完成历史数据导入与验证后再切换；同一空间不要同时运行旧文件采集和新协议采集。

适配器将稳定的本地消息 ID、会话、人物和结构化提及转换为通用消息协议，通过宿主数据目录中的持久队列投递。断线时继续聊天，恢复后补投；服务逐条拒绝的消息保留并显示同步错误。

回复前请求 `recall`，成功加入上下文后才确认 `adoptions`。助手记忆写入必须携带已接收消息的证据 ID，缺少证据会明确失败。

独立协议启用并重载插件后，新增 `remember_thing` 工具记录新梗、术语、作品或项目。模型只需给名称，可选补充原意；空间和本轮已核对的用户消息引用由适配器补齐。只有名称时保留为待解释候选，不编定义。后台整理也能独立发现新事物，不依赖聊天模型每次主动调用工具。

工具说明使用日常触发条件，一次明确表达即可记录。若一直没有调用，请同时检查工具总开关、memory 分类、插件启用状态和单工具覆盖；工具注册成功不表示当轮一定暴露。细节见[新事物记忆](../../docs/thing-memory.md)。

管理页使用管理员凭据；插件仅持有项目凭据。服务源码与完整协议见仓库根目录。
# 0.32 场景档案

通用协议启用时新增 `remember_scene` 与 `query_scene`。有人说明群规、专属梗、频道定位或游戏房间约定时，一次明确说明即可提交；跨渠道补充先作候选。私聊可查询管理员标记允许跨渠道使用的场景摘要，原话不会跟随开放。条目纠正、关联影响预览与账号绑定在独立管理页操作。

旧 `skills/group-memory` 文件用 `tools/import-group-memory.mjs <file.json> <spaceId>` 显式导入。通过环境变量提供 `VEC_MEMORY_URL` 和 `VEC_MEMORY_ADMIN_TOKEN`，不要把凭据写入命令参数或链接。导入保留旧记录但不把旧 hits 当作证据。核对后关闭旧群记忆的写入与注入，再启用新场景工具；不要同时维护同一场景的两份真值。
