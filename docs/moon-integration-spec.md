# 溟月接入首版规格

## 问题

角色需要延续自己的念想和有出处的约定。其他项目需要继续使用原有事实、召回和备份。

## 方案与顺序

1. 完成时间记忆和会话级念想、待办的独立读写接口。
2. 用真实服务处理器验证隔离、恢复及普通召回，提交并先推送记忆库更新。
3. 制作溟月对接模块，绑定空间、角色和实际会话，替换聊天记忆读取，验证失败时的行为。

## 用户故事

1. 作为普通调用方，我希望仍按原顺序读到同一份通用记忆。
2. 作为记忆库使用者，我希望查到现状、变化历史及各自出处。
3. 作为角色，我希望重启后接回同一会话的念想。
4. 作为新角色，我希望拥有独立的主观记录。
5. 作为其他获准项目，我希望能读到可交接待办。
6. 作为空间维护者，我希望能完成或取消旧待办，避免它反复出现。
7. 作为迁移者，我希望普通备份可独立使用，完整搬迁时可选角色记录。
8. 作为会话参与者，我希望其他会话无法取得这边的约定正文。

## 实现决策

- 角色记录和通用待办使用独立作用域及接口。角色扩展不会进入普通召回。
- 待办必须关联同会话的已接收用户消息。念想可选关联同会话证据。
- 读写使用既有空间权限。会话和角色由受信调用方绑定。
- 原始证据不足的记录在查询时隐藏。扩展复用备份容器，角色记录由显式选项携带。

## 验收

在服务 API 边界验收复开会话、角色和会话隔离、可交接待办、幂等、带证据恢复及普通召回。适配层另验收实际请求的作用域和凭据。

## 首版范围

念想与待办优先。原插件宿主联调、心事、她的一天、自动抽取和线上切换各自验收。
