# vec-memory 0.32.2 安装与接入手册

- 适用：0.32.2 分享总包、`vec-memory-0.32.2.zip` 和 QQ 适配器包；文档日期 2026-11-01。
- 分享总包同时带有发行包、本文、完整设计文档、客观评估和协议示例。直接使用请先解压里面的主发行包，再执行启动步骤；设计资料可离线阅读。
- 读者：不想改代码的 QQ 用户，以及接其他项目的开发者。
- 以当前源码为准。旧手册里的 `8088`、`manage.html`、手工准备 QQ 人物文件、`/api/vec` 均不是当前接入口；当前是 `8091`、`/standalone.html` 和 `/api/v1`。旧路由仅为兼容保留。
- **本机默认免凭据**（0.32.2 起）：服务只监听 `127.0.0.1`，浏览器打开 `http://127.0.0.1:8091/standalone.html` 即可管理，不出现登录框。带了无效凭据仍返回 401，非回环来源一律要求 Bearer。要强制鉴权，用 `--require-auth` 启动；管理员与项目凭据一直保留在 `access.json`（哈希）与 init 时打印的明文里，随时可切回。
- 这是个人自托管工具，不是成熟 SaaS。先在小库验收，确认后再接真实数据。

> **0.32.1 补丁说明**：自动人物印象在整个请求中合计最多 2 条字段级关键词线索，不再整卡铺开；只有人物 `semantic`/`profile` 受此上限约束，其他层照常。显式工具查询用 `purpose:"query"` 走完整检索。A 谈 B 不要求 B 发言；昵称只在无歧义精确命中时识别，结构化提及登记稳定身份；B 的档案保留 A 的转述来源并标注“含他人转述”，不写成 B 自述。跨渠道原话不开放，新空间默认同场合，管理员明确保存 `profileCrossScope` 或 `profilePolicy` 后才按既有档案共享规则读取。QQ 适配层旧协议与独立协议都改了提示词和搜索入口，但生产基础配置本次不切换，仍按旧协议运行；没有实际 QQ 对话实测，提示词改善不等于模型一定会调用工具。验证结果见补丁说明。

## 1. 包结构与运行前提

主包解压后的 `vec-memory-0.32.2/` 就是项目根：

```text
vec-memory-0.32.2/
├─ install.cmd  init.cmd  start.cmd  安装与接入手册.md
├─ package.json  package-lock.json  README.md  PROTOCOL.md  release-manifest.json
├─ src/  tools/  web/  openapi/  test/
├─ adapters/qq-agent/
├─ examples/standalone/
└─ docs/
```

- `install.cmd`：只在项目根执行 `npm ci`，不初始化数据。
- `init.cmd`：初始化空数据根，输出一次管理员凭据；第一个参数可传绝对数据根。
- `start.cmd`：启动服务，不自动初始化；第一个参数可传同一个绝对数据根。
- 默认数据根是程序目录同级的 `vec-memory-data`。例如项目在 `E:\vec-memory-0.32.2`，默认是 `E:\vec-memory-data`。
- 发行包不捆绑 Node 运行时、`node_modules`、Python 运行时、模型或个人数据；首次安装需要 Node.js >= 22.5 和联网执行 `npm ci`。
- 适配器包内部的 `memory-vec/` 是 QQ-Agent 适配器源码，不是独立服务，也不包含宿主程序。

数据根必须可写，建议使用绝对路径；含空格时加引号。一个数据根同时只能有一个服务进程写。已有数据根不要再次初始化；升级时解压新程序、保留原数据根，备份后直接用旧根启动。

## 2. 空库启动

### 2.1 Windows 双击路径（适合 QQ 用户）

1. 将主包解压到有写权限的目录，例如 `E:\vec-memory-0.32.2`，不要在压缩包预览窗口中直接运行。
2. 双击 `install.cmd`，等待 `npm ci` 完成。首次需要联网；失败时先看窗口里的网络/Node 版本错误。
3. 双击 `init.cmd` 使用默认数据根，或在项目根的命令行执行 `.\init.cmd "E:\vec-memory-data"` 自定义。窗口会输出 `adminToken`，只显示一次，立即存入密码管理器。
4. 双击 `start.cmd`，或执行 `.\start.cmd "E:\vec-memory-data"`。保持窗口运行，按 `Ctrl+C` 停止。
5. 浏览器打开 `http://127.0.0.1:8091/standalone.html`；`http://127.0.0.1:8091/health` 只用于确认进程存活。服务默认监听 `127.0.0.1:8091`，不要同时双击两次启动同一数据根。

### 2.2 跨平台 CLI

下面以 Windows 路径演示；Linux/macOS 将程序和数据目录换成自己的绝对路径，命令不变。Windows 双击脚本在其他系统上不用运行。

```powershell
cd E:\vec-memory-0.32.2
npm ci
npm run init -- --root "E:\vec-memory-data"
npm start -- --root "E:\vec-memory-data"
```

也可直接调用：

```powershell
node tools/standalone-server.mjs init --root "E:\vec-memory-data"
node tools/standalone-server.mjs serve --root "E:\vec-memory-data" --host 127.0.0.1 --port 8091
```

非 Windows 将盘符路径换成 `/srv/vec-memory-data` 等绝对路径，命令相同。`init` 发现数据根已有 `access.json` 会报 `Already initialized`。此时不要删除 `access.json` 或重建数据根；应确认路径是否写错，已有数据直接用 `start` 启动。

## 3. 管理员页：凭据、项目与空间

先分清两类凭据：

| 凭据 | 来源 | 用途 |
|---|---|---|
| 管理员 token | `init` 仅输出一次 | 登录管理页；创建项目/空间、改模型设置、备份恢复、账号绑定、场景确认 |
| 项目 token | 创建项目时仅显示一次 | 业务 `/api/v1/spaces/...` 调用；QQ 适配器的 `serviceToken` |

管理页操作顺序：

1. 在“管理员凭据”输入 `adminToken`，点“连接并刷新”。token 只留在页面内存。
2. 在“项目与空间”填项目 ID（如 `qq-project`），点“创建项目”。页面显示的 token 立即保存，关闭后不能再次查看。
3. 填空间 ID（如 `qq-a`）和“所属项目 ID”（`qq-project`），点“创建空间”。空间 owner 是项目，不是某个人。
4. 需要让别的项目只读时，在该空间填“允许读取此空间的项目”，逗号分隔后保存；留空保存即撤销全部共享读取。
5. 用项目 token 做一次业务验收，再交给适配器或接入方。

管理员 token 不发给插件、接入项目或模型；项目 token 也不能调用管理接口。管理页的跨场合总览是管理员视图，不会扩大任何项目 token 的空间或场合权限。凭据不要写进 URL、文档、聊天记录或 git。

## 4. 模型设置（可选，默认不自动花钱）

模型按空间配置，位置在管理页“模型与记忆”：先在上方填空间 ID，点“读取设置”，编辑 JSON 后点“保存设置”。页面显示的是设置值，密钥不会回显。

示例（按自己的 OpenAI 兼容服务替换地址和模型名）：

```json
{
  "embedBaseURL": "http://127.0.0.1:8081/v1",
  "embedModel": "local-embedding",
  "llmEndpointKind": "local",
  "llmBaseURL": "http://127.0.0.1:8080/v1",
  "llmModel": "local-llm",
  "consolidateEnabled": false,
  "autoIndexEnabled": false
}
```

- LLM 与 embedding 分开配置。`embedding` 用于向量检索，`llm` 用于整理/抽取；一个不可用不影响另一个。
- 地址填 OpenAI 兼容的 base URL，程序会拼 `/embeddings` 或 `/chat/completions`；多数云端地址需要以 `/v1` 结尾。
- 密钥字段为 `embedApiKey`、`llmApiKey`。只在实际配置时填写；空字符串表示保留旧值，`null` 才删除。不要把密钥贴到聊天或文档。
- 自动整理和自动索引默认关闭。上面的 `false` 不要急着改；可先在页面手动点“整理记忆”或“构建索引”，确认任务完成后，再决定是否开启自动任务。
- 模型设置好后用“记忆状态”核对 `embeddingConfigured`、`llmConfigured`。`llmEndpointKind` 按实际填 `local` 或 `external`，不建议留空。

不配模型也能完成最小闭环：消息会持久化，召回会走关键词路径。没有 LLM 时整理任务会失败并保留原料；没有 embedding 时 `recall.actualMode` 可能是 `keyword`，并可能带 `EMBED_UNCONFIGURED`/`EMBED_FAILED` 降级原因。不要把关键词结果说成向量成功。

## 5. QQ-Agent 适配器

### 5.1 它不是即插即用的跨版本宿主桥

适配器只负责把当前宿主提供的消息、会话、人物和工具调用转换成 v1 协议。它不包含 QQ-Agent 宿主本体，也不保证兼容所有宿主版本；宿主 API 不同就需要按自己的钩子改造。不要覆盖整个宿主配置，只增加/修改 `memory-vec` 的插件设置。

### 5.2 安装和配置

1. 先确保独立服务已启动，管理页已创建项目和空间。
2. 将适配器包里的 `memory-vec/` 放到宿主插件目录（当前说明为 `plugins/memory-vec/`），用宿主自己的插件安装/启用方式加载。
3. 在“设置 → 向量记忆库”中只改以下字段，保存后重载插件：

```json
{
  "protocolV1": true,
  "serviceBaseURL": "http://127.0.0.1:8091",
  "spaceId": "qq-a",
  "serviceToken": "<项目 token，不是管理员 token>",
  "autoStartService": false
}
```

默认值是 `protocolV1:false` 和 `serviceBaseURL:http://127.0.0.1:8088`，与独立服务不一致。要使用 v1 时，必须显式打开 v1、改成 `8091`、填空间 ID 和项目 token；v1 下模型只在服务端空间设置里配，适配器旧 embed/llm 字段不是数据面配置。想手动启动服务时设 `autoStartService:false`，先运行 `start.cmd`，不要依赖插件拉起的旧路径。

本次 0.32.1 补丁不修改现场配置，也不把生产环境从旧协议自动切到独立协议。已有生产基础配置仍按旧协议运行即可；上面是启用 v1 时的配置，是否切换要另行验证，不能把本补丁当成协议迁移。

### 5.3 工作方式和工具

- 适配器用宿主数据目录中的持久队列投递消息；服务断线时聊天可继续，恢复后补投。服务返回 503 维护时保留队列，退避重试。
- 启用 v1 并重载后，工具包括 `memory-vec__remember`、`memory-vec__search`，以及新梗/场景工具 `memory-vec__remember_thing`、`memory-vec__remember_scene`、`memory-vec__query_scene`。
- 自动注入使用 `purpose:"automatic"`：人物 `semantic`/`profile` 合计最多 2 条字段级关键词线索，不是整张人物卡；其他层不受这 2 条限制。显式 `memory-vec__search` 使用 `purpose:"query"`，可以拿更多人物字段和来源，但仍受条数、场合和共享授权限制。
- 回复前召回成功加入上下文后才确认采用；适配器不会把“打印了召回结果”当成真正注入。
- 工具注册成功不等于本轮一定暴露，也不等于模型一定调用。若模型一直不调用，按顺序检查：宿主工具总开关、memory 分类、插件启用状态、单工具覆盖、宿主运行时限制、是否已重载 v1。不要只看工具列表。
- 旧群记忆先显式导入并核对，再关闭旧文件采集和注入，最后启用新协议采集。同一空间不要同时运行旧文件采集和新协议采集。

## 6. 接其他项目：不依赖模型的最小闭环

业务前缀是 `/api/v1/spaces/{spaceId}`，所有请求都要 `Authorization: Bearer <项目 token>`。先在管理页建立 `demo-project` 项目和其所属的 `demo-space` 空间，下面输入该项目的 token；也可以把 `$Space` 换成你已有的测试空间。下面是可直接粘贴到 PowerShell 的合成示例；不要把示例 ID、正文当成真实用户资料。

```powershell
$Base  = 'http://127.0.0.1:8091'
$Token = Read-Host '项目 token'
$Space = 'demo-space'
$H = @{ Authorization = "Bearer $Token" }
$Scope = @{ kind = 'private'; id = 'demo-chat' }

$Msg = @{ messages = @(@{
  messageId = 'demo-msg-001'; conversationId = 'demo-chat'; actorId = 'demo-user'
  role = 'user'; timestamp = '2026-11-01T00:00:00Z'
  text = '合成示例：我喜欢不加糖的绿茶。'; scope = $Scope
}) } | ConvertTo-Json -Depth 8
$Ingest = Invoke-RestMethod -Method Post -Uri "$Base/api/v1/spaces/$Space/messages" `
  -Headers $H -ContentType 'application/json; charset=utf-8' -Body $Msg
$Ingest.results | Format-Table
if ($Ingest.rejected -gt 0) { throw '有消息被拒绝，检查 results 后再重试' }

$Entity = @{ displayName = '合成用户'; surfaces = @('demo-user'); aliases = @('小茶') } |
  ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Put -Uri "$Base/api/v1/spaces/$Space/entities/demo-user" `
  -Headers $H -ContentType 'application/json; charset=utf-8' -Body $Entity | Out-Null

$Memory = @{
  operationId = 'demo-memory-001'; actorId = 'demo-user'; kind = 'preference'
  text = '喜欢不加糖的绿茶'; scope = $Scope; source = 'manual'
} | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri "$Base/api/v1/spaces/$Space/memories" `
  -Headers $H -ContentType 'application/json; charset=utf-8' -Body $Memory

$RecallBody = @{ query = '不加糖的绿茶'; conversationId = 'demo-chat'
  actorIds = @('demo-user'); scope = $Scope } | ConvertTo-Json -Depth 6
$Recall = Invoke-RestMethod -Method Post -Uri "$Base/api/v1/spaces/$Space/recall" `
  -Headers $H -ContentType 'application/json; charset=utf-8' -Body $RecallBody
$Recall.actualMode
$Recall.items | Format-Table layer, text, id
$Recall.block
```

这段闭环不需要 LLM 或 embedding：写消息、登记实体、写人工记忆（`source:"manual"`）、召回四步应成功；实际注入后再走 6.1 的第五步 adoption，没有真实注入就不要确认。若没有 embedding，`actualMode` 通常是 `keyword`，这是降级而非向量检索。

### 6.1 采用确认不是演示打印

上面的 `$Recall.block` 和 `items` 只是返回文本。只有这些内容**真的被拼进一次实际模型请求**，才谈得上采用。不要因为控制台打印、页面预览或示例脚本输出了 items 就确认 adoption。

确认片段可选择执行，且只选真正进入上下文的那几条：

```powershell
$Chosen = @($Recall.items | Where-Object { $_.text -eq '喜欢不加糖的绿茶' } |
  ForEach-Object { $_.id })
$Chosen
if ($Chosen.Count -eq 0) { throw '未找到目标条目，不要伪造采用' }
# 人工核对 $Chosen 已进入实际模型上下文，且 recall 仍在 60 秒收据有效期内，再执行：
$Adopt = @{ receiptId = $Recall.receiptId; itemIds = $Chosen } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$Base/api/v1/spaces/$Space/adoptions" `
  -Headers $H -ContentType 'application/json; charset=utf-8' -Body $Adopt
```

收据 60 秒过期、绑定调用项目，确认时还会复查共享授权。过期后要重新召回并重新注入，不能续期；省略 `itemIds` 表示确认收据内全部内容，生产代码不要偷这个懒。采用只证明“加入上下文”，不证明模型真正利用或事实正确。

### 6.2 稳定 ID、冲突与客户端示例

- `messageId` 用平台消息 ID 或自己的稳定记录 ID；同 ID 同内容重试是 `duplicate`，不同内容重试是 `conflict`。
- `operationId` 用于记忆、发现、任务等重试；同 ID 不同正文返回 `OPERATION_CONFLICT`。冲突时保留原 ID、查清差异，不要换一个新 ID 掩盖。
- `scope` 与 `actorId` 必须是稳定标识，不要用昵称。`actorId` 先登记实体；不同空间不自动合并同名实体。
- 每批消息最多 500 条；HTTP 200 仍要检查逐条 `results`，某条失败不会回滚其他条。
- 现有示例使用 `VEC_BASE_URL`、`VEC_TOKEN`、`VEC_SPACE`。可选 `VEC_RUN_CONSOLIDATE=1` 才提交整理任务；`VEC_CONFIRM_ADOPTION=1` 只应在真实采用后设置，默认不要设置。

```powershell
$env:VEC_BASE_URL = 'http://127.0.0.1:8091'
$env:VEC_TOKEN = Read-Host '项目 token'
$env:VEC_SPACE = 'demo-space'
node examples/standalone/client.mjs
python examples/standalone/client.py
```

Python 示例用标准库；Node 示例用内置 `fetch`。示例会打印召回结果，自带的采用确认分支是演示，不等于已经注入真实 LLM 上下文。

## 7. 新梗、场景、跨渠道共享与账号

### 7.1 新梗与新事物

QQ 中有人解释新梗、术语、作品或项目时，`remember_thing` 记录名称和用户原意；只听到名称也能记成待解释候选，不应编定义。后台整理也可发现新事物，但不启用自动任务，且需要 LLM。

开发者用 `POST /discoveries`，必须有同场合、已接收的 user 消息作为 `evidenceIds`；名称要出现在证据里。省略 `statement` 就是候选，不能把候选当已核验知识。`GET /subjects` 和详情查询都要带 `scopeKind`、`scopeId`；纠正/撤回用 `subjects/{subjectId}/revisions`，保留历史，`expectedRev` 过期要重新读取。详见[新事物记忆](thing-memory.md)。

### 7.2 场景档案和逐条共享

群、频道、游戏房间都可建场景。QQ 用户说“记下本群规矩/定位/梗/约定”时由 `remember_scene` 提交，“查一下某个群/频道的约定”时用 `query_scene`。私聊能查的只是管理员标记为跨渠道可用的摘要，原话不会跟着开放。

开发者通过 `POST /workspace` 的 `action` 操作：`ensureScene` 建场景、`entry` 写观察或候选、`query`/`scenes` 读取、`support` 用目标场景原话支持候选。外部渠道补充先作候选，候选也要有提交场合的用户原话，不会自动成为原场景共识；`confirm`、`shareable` 和已有条目修订只允许管理员。跨渠道共享是**逐条**的，共享查询不带外部原话、历史或旧导入原记录。

### 7.3 账号绑定和权限

账号绑定只能由管理员在“人物档案与印象”里显式确认，绑定的是已登记的稳定账号 ID，不按昵称相似度自动合并，也不批量绑定。解绑是带 `expectedRev` 的显式操作，不删除原记录。

绑定只是读取时汇总，不改变原始证据归属，不扩大空间、场合或项目权限。管理页勾选“管理视图：汇总此人在本空间各场合的档案”也只在本空间内展示；普通项目 token 的 `recall` 仍按当前 `scope` 和 readers 过滤，跨空间读取还需 `sharedSpaceIds` 显式列出并获授权，不会自动串联。不要把“绑定”宣传成私聊原话可以在任意群自动出现。

### 7.4 第三人称人物与自动线索

- A 问“B 是做什么的”时，B 不必在当前会话发过言。先给 B 登记稳定账号、显示名或别名；昵称只有在无歧义精确命中时才识别，同名或不确定时应询问稳定 ID，不要猜。
- 自动注入只给人物 `semantic`/`profile` 合计最多 2 条字段级关键词线索，不能当完整档案；需要更多信息时由模型调用 `memory-vec__search`（`purpose:"query"`），或由用户明确要求查某人。模型是否调用工具仍由宿主和模型行为决定。
- A 明确介绍 B 时，内容记到 B 的档案，来源保留 A 的转述并标“含他人转述”，不能当成 B 自述。只提问、猜测或玩笑不写成肯定事实。
- 跨渠道原话仍不开放；新空间默认同场合，只有管理员明确保存 `profileCrossScope` 或 `profilePolicy` 后才按既有档案共享规则读取。不能承诺任意跨渠道都能查到。
- 本次没有实际 QQ 对话实测，不能声称模型一定会调用工具；提示词改善与工具调用行为是两件事。相关验证结果见补丁说明。

## 8. 远程 HTTPS 反向代理

不要把 `8091` 直接暴露到公网。使用 HTTPS 反向代理，并保留 Host 和协议头，例如：

```nginx
location / {
  client_max_body_size 1024m; # 允许备份上传；服务仍自行检查大小与权限
  proxy_pass http://127.0.0.1:8091;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

浏览器打开 `https://memory.example.com/standalone.html`。服务会校验浏览器 `Origin` 必须与 Host/协议一致；代理未保留原始 Host 时可能得到 `403 ORIGIN_DENIED`。

浏览器跨源与后端 HTTP 客户端不同：从别的站点用浏览器直接 fetch 会被同源检查挡住，也不应靠加 CORS 头绕过；Node/Python 服务端客户端通常不带 `Origin`，但仍应走 HTTPS。管理页有 `frame-ancestors 'none'`，不要嵌 iframe，直接开独立页面。

## 9. 备份、导入、迁移

先读[备份与恢复操作说明](operations/backup-restore.md)和[独立服务离线迁移](operations/standalone-migration.md)。不要把 `access.json`、`spaces/`、`settings.json`、JSONL 日志等核心文件手工复制拼库。

- 完整服务备份在管理页“备份与导入”做，密码至少 8 位，下载到另一块磁盘；完整备份含模型密钥和凭据哈希，空间备份不含这些和共享授权但仍有记忆数据，都要按敏感文件保管，空间备份通常也建议加密。
- 恢复前先“检查并预览”，记下 checksum；完整恢复生成旁置目录，验证后由人停旧服务、切换到新根启动，不自动切换。
- 恢复后自动任务暂停、收据清空；空间导入不继承 readers，替换会保留 `.rollback-*`，不做自动合并。
- 备份/导入期间新请求可能返回 `503 MAINTENANCE`。这是维护窗口，保留原 `messageId`/`operationId`，退避后重试，不要强杀服务。

旧群记忆用显式导入，不扫描宿主目录：

```powershell
$env:VEC_MEMORY_URL = 'http://127.0.0.1:8091'
$env:VEC_MEMORY_ADMIN_TOKEN = Read-Host '管理员 token'
node tools/import-group-memory.mjs "E:\old\group-memory.json" "qq-a"
Remove-Item Env:VEC_MEMORY_ADMIN_TOKEN
```

凭据只放环境变量，不写命令参数。导入结果是未核验候选，旧 hits 不作为新证据；人工核对后，先关闭旧群记忆的写入与注入，再启用新场景工具，不要同时维护两份真值。

旧版数据迁移先执行 `tools/standalone-migrate.mjs migrate`，再用 `tools/standalone-import.mjs` 转成通用原料，完整步骤和目标必须为空的限制见[离线迁移说明](operations/standalone-migration.md)。升级 0.32.0 时的记录仍保留在[升级说明](upgrades-20261101.md)；升级到 0.32.1 沿用同一流程：先备份、停旧服务，用新程序目录配旧数据根启动，绝不再次 `init`。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| `401 UNAUTHENTICATED` | 没带 Bearer 或 token 无效。管理页用管理员 token，业务与适配器用项目 token；项目 token 调管理接口是 403，不是 401。 |
| `403 FORBIDDEN` | 项目不是该空间 owner，也没有 readers 授权；或误调管理员路由。浏览器另见 `ORIGIN_DENIED`。 |
| `503 MAINTENANCE` | 正在备份/导入。保留原 ID 和请求，退避重试；QQ 队列不要手工清空。 |
| 整理/索引任务 `failed` | 看 `code`/`message`。`LLM_UNCONFIGURED` 补 LLM；`EMBED_UNCONFIGURED` 补 embedding。修好后新建任务，失败任务不会自动重试。 |
| 模型端点返回 401/403 | 这是模型提供方的鉴权失败，不是 vec-memory token；检查对应的 embedding/LLM 地址、key、模型名。 |
| 召回是关键词结果 | 看 `actualMode`/`degraded`。没有 embedding 或调用失败会降级，不是向量检索成功。 |
| 工具不出现或模型不调用 | 查工具总开关、memory 分类、插件启用、单工具覆盖，并重载插件；注册成功不等于当轮暴露，模型也可能不调用。 |
| `OPERATION_CONFLICT`/消息 `conflict` | 同一稳定 ID 被用于不同正文。查清差异并人工处理，不要换 ID 掩盖。 |
| 启动报另一个服务拥有数据根 | 同一数据根已有写者。正常停旧进程并确认 `.service.lock` 对应进程退出；不要手工强删锁。 |
| `/health` 正常但业务失败 | `/health` 只表示进程存活，不证明认证、模型、任务或数据正确；继续看 `/status`、任务和错误正文。 |

## 11. 验收清单（8 步）

1. 核对主包结构、发行包标注的 `package.json` 版本（本补丁目标 `0.32.1`），确认没有 `node_modules`、Node、模型或个人数据；本机 `node -v` >= 22.5。
2. 用全新临时目录执行 `install.cmd`、`init.cmd`、`start.cmd`，确认 `/health` 和 `/standalone.html` 可访问，数据根路径正确。
3. 管理页登录，创建测试项目和空间；确认项目 token 只能操作授权空间且不能调管理接口，管理员 token 不交给接入方。
4. 不配模型跑第 6 节闭环：消息、实体、`source:"manual"` 记忆、`recall` 均成功；同 `messageId` 同内容重发为 duplicate，改正文为 conflict；确认 `actualMode` 的实际值。
5. 用一个会把条目真正拼进模型请求的测试客户端验证 adoption 前置条件；不要在普通演示、假注入或只打印结果时确认。
6. 如配模型，手动提交整理和索引任务并轮询到 completed；确认自动任务仍关闭，再抽查召回层级/来源；不把关键词降级当向量成功。
7. 安装 QQ 适配器：生产基础配置可继续保持旧协议，本次补丁不要求切换；若单独验证 v1，再显式设 v1、8091、spaceId、项目 token、`autoStartService:false`，重载后确认工具；断网/重启验证持久队列补投，恢复后不重复消息。
8. 做一次完整备份、预览、旁置恢复和权限复核：readers 撤销/授权生效，跨场合总览不扩大项目权限；全过程不覆盖生产、不手工复制核心文件。
