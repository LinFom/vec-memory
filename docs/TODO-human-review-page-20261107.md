## 4. 交给前端负责人的实现口径（本轮**不实现**）

以下是建议 spec，供前端负责人取舍；**本文件不构成实现承诺**。

### 4.1 范围

- 一个「待核对」视图，聚合四类来源：① 未核验的历史导入候选；② `preview.suspected` 共用证据条目；③ `mention` / 待确认的新事物候选；④ `RESTORED_REVIEW_REQUIRED` 任务。
- 每条至少展示：条目文本、场合 / 场景、来源引用（原始文件 + 行号，或稳定记录 ID）、当前状态、所属空间。
- 每条至少可操作：确认、修订、撤回、**保留并列**（矛盾说法并列 + 来源引用，服务不裁决）。

### 4.2 硬禁止（对齐既有设计，别做成「智能合并」）

1. 不按语义相似度批量合并；「相似」只能作为提示，决定权逐条在人手里。
2. 不自动确认、不默认全选、不用出现次数当可信度（`CONTEXT.md:16`、`docs/thing-memory.md:10`）。
3. 不物理删除旧版本：修订保留历史、撤回留墓碑、同内容重投不复活（`docs/完整设计文档.md:267-270`）。
4. 不把「人工核对过」写成数值可信度分数、不参与召回打分；采用次数仍只是采用（`CONTEXT.md:16`）。
5. 不绕过管理员凭据与空间 / 场合隔离；跨空间显式授权仍逐条复核（`docs/standalone-protocol.md:14,64`）。

### 4.3 后端依赖判断（先别造第二套状态）

- 优先用**现有 API** 聚合：场景条目 preview、主体/新事物详情、任务列表、`/facts/merged`。
- 若现有接口不足以列出未核验导入候选，**另开后端票**补一个只读聚合接口；不要在前端本地维护一份「已核对」状态 —— 那会变成第二个真值源。
- 未核验标记的定义以票 01「通用记忆导入契约」为准（`docs/memory-import-contract-20261107.md`），不要在页面里另造枚举。

### 4.4 建议验收（可测，供前端负责人与评审用）

- [ ] 造 N 条候选，队列能全部列出，且条数、来源引用、场合与服务端一致
- [ ] 逐条确认后状态变化、旧版本与来源历史仍在；撤回留墓碑，重放不复活
- [ ] 对同一条 `suspected` 能单独处理，不会连带自动修改共用证据的其他条目
- [ ] 矛盾陈述选择「保留并列」后，两条都在、各自来源可点开
- [ ] 跨空间 / 跨场合不串数据；非管理员只读或无操作入口
- [ ] 队列为空时显示空态，不显示假入口；接口失败显示可读错误，不显示空列表冒充「没有待办」
- [ ] 全部操作走服务端既有写入口，页面不落本地状态；刷新后状态一致
- [ ] 不新增第二个注入块、不改召回顺序（本页是管理面，不是注入面）
