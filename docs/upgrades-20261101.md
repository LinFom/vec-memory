# 2026-11-01 升级说明（目标 0.32.0）

- 日期：2026-11-01
- 目标版本：0.32.0
- 基线：本仓库当前源码与测试
- 定位：个人自托管记忆服务；不是生产全验证，也不是成熟 SaaS

## 1. 这次升级是什么

把记忆服务从“宿主插件 + 旧数据目录”收敛为可独立启动、可认证、可备份/恢复、可人工纠正的服务，同时保留 Node.js 和现有记忆引擎。

不是：

- 不重写 Python；
- 不替换 Node.js/现有引擎；
- 不增加 MCP 记忆传输；
- 不把文件存储改造成数据库；
- 不自动合并空间、不自动切换恢复根、不自动重建旧向量。

## 2. 先更正旧叙述

以下说法在 0.30 时代可能成立，但现在不能再用于描述独立服务：

| 旧说法 | 现在的事实 |
|---|---|
| “没有认证” | 所有 `/api/v1` 都要 Bearer；管理接口要管理员；只有 `/health` 和静态页不要求 |
| “必须绑定 QQ-Agent 宿主目录” | 独立服务用 `init|serve --root`；项目/空间/凭据自己管理；旧宿主只做兼容读取/显式导入 |
| “消息只能从宿主存档来” | 可直接 `POST /messages`，空间自己的 `input/messages.jsonl` 持久化 |
| “没有权限隔离” | owner/readers 分级；共享读取显式授权；检索/采用复核 |
| “场景只能是一个群” | 场景有 `type`，群/频道/游戏房间可建档；但底层 `scope.kind` 仍只有 private/group |

## 3. 行为变化清单

### 3.1 独立服务与认证

- `tools/standalone-server.mjs init --root <dir>` 初始化，输出一次管理员 token。
- `serve --root <dir>`，默认 `127.0.0.1:8091`。
- 公开契约 `/api/v1`；旧 `/api/vec` 只作兼容，不是新接入接口。
- HTTP 与进程内 `createService(...).handle(...)` 走同一实现。
- 管理页 `/standalone.html`；管理员 token 只在页面内存。

### 3.2 场景档案

- 新增 `workspace` 的 `scene`/`ensureScene`/`entry`/`query`/`preview`/`retract`/`support`/`link` 等动作。
- 场景条目支持 candidate/observed/confirmed/retracted；撤回/纠正保留 history 和墓碑。
- 跨渠道只逐条 `shareable`；共享摘要不带证据/历史；自动日常注入只当前场景，显式 `sceneId` 才读共享。
- 非管理员在外部渠道提交候选，在目标场景凭已接收的用户证据提交 observed；管理员才能确认/共享；目标场景明确原话 `support` 可把候选升为 observed。
- 重复内容不新增条目；同一证据不重复计数；不同说法可并存。

### 3.3 人物人工修订与主体修订

- 人物条目支持 `preview`/`revision`：`replace`/`hide`/`restore`，带 etag/preview token。
- 人工新增/修订在独立日志，读时投影；机器再抽取不覆盖人工值。
- 主体（新事物）支持 `correct`/`retract`，保留原观察/证据/历史；`expectedRev` 过期 409。
- 人物修订到场景的联动用 `correction-intents.jsonl` 持久意图恢复；**不是多文件原子提交**。

### 3.4 账号绑定

- 管理员确认 `link`；`a/b` 必须是已登记账号；`confirmed:true`。
- 解绑用 `active:false` + `expectedRev`；不删除原记录。
- 读时投影传递闭包；不改写原账号；不放大空间权限；人物读取仍按当前 `scope` 过滤。
- 不要宣传“绑定后任意场合人物原话自动互通”。

### 3.5 normalizer v3 与歧义昵称

- `NORMALIZER_VERSION = 3`。
- 同一 surface 撞名：先到者获得 `surfaceIndex`，冲突进入 `ambiguous` 列表。
- 歧义 surface 归一化时用中性替换，不再强行归属某个人；稳定账号 ID 仍独立。
- `蜂蜜柚子茶` 与 `柚子`：独立的 `resolveKnown` 标签仍可分；“柚子”作为撞名 surface 不再输出任一人的标签；`蜂蜜柚子茶` 仍映射到先登记实体。
- 旧向量因 `normalizer` 身份变化需要兼容性检查；不会自动花钱重建。
- 不声称历史误归属已经全部修复；需要重建/人工核对。

### 3.6 事件向量搬运与重建续跑

- `planEventCarry` 的来源身份只取旧行/旧代记录；第二次搬运优先 `carryIdentity`。
- 旧库缺 endpoint/revision/normalizer/documentFraming 记录 → `unknown`，默认 fail-closed；不能把中间代 encoding 当来源证明。
- `rebuild-job.json` + 代目录 + `vector-active.json` 指针；已写入条目续跑跳过，继承计数。
- 旧代在重建期间只读；未 publish 的新代不服务查询。
- 只有显式 `index` 任务才准备新代；不会自动重建。

### 3.7 召回 hard 阈值

- query 时 `selectInjectLines` 用 `hard`；无 query 仍 `boost`。
- 6 条合成标注：
  - before：precisionAt8 2/3，recallAt8 1，falseInjectionRate 1/6；
  - after：precisionAt8 1，recallAt8 1，falseInjectionRate 0。
- 只验证微型关键词语义检索；不验证真实 LLM 抽取、讽刺、长期记忆真实优势、跨产品比较。
- 保留：
  - `docs/recall-evaluation-before-20261101.json`
  - `docs/recall-evaluation-20261101.json`

### 3.8 备份/导入/恢复

- 完整服务加密备份（密码 ≥8）；空间备份去掉模型密钥/服务授权，默认建议加密。
- 在线备份短暂 503；离线 `create` 必须停库。
- 完整恢复到旁置目录，验证后人工停旧、切换启动根。
- 空间导入新空间或显式替换，保留 `.rollback-*`，不自动合并。
- 恢复后自动任务暂停、receipts 清空、queued/running 任务 failed。
- 归档 512 MiB 未压缩上限；不是大型流式数据库备份。

### 3.9 UI 与 QQ 适配

- 管理页新增场景、人物修订/历史、绑定/解绑、备份预览；trait 小卡在前，动态印象在后。
- QQ 适配层 protocol v1 工具：`remember`、`remember_thing`、`remember_scene`、`query_scene`、`search`；消息队列持久化。
- 适配层默认 `serviceBaseURL=http://127.0.0.1:8088`，与服务默认 8091 不一致；升级时必须显式对齐。
- 适配层文件头已同步为 0.32.0；不要把它当服务版本。

## 4. 目标与实现差距（升级时必须知道）

| 目标 | 当前实现 | 差距 |
|---|---|---|
| 完整服务密码加密备份含配置/身份密钥/访问凭据状态 | 已实现 AES-GCM + scrypt；`access.json`/settings/secret.key 在归档内 | 版本统一为 0.32.0 |
| 空间备份默认不带模型密钥/服务授权 | 已过滤 settings 的 key/token/secret/password；不含 access.json | 仍含 `normalizer/secret.key`；无密码时未加密 |
| 短暂停写、队列待投递 | 服务 maintenance 503；QQ 协议队列/outbox 持久化 | 服务端没有通用 HTTP 消息队列；普通客户端要重试 |
| 完整恢复旁置验证后手动切换 | 服务恢复 `root.restore-<uuid>` + audit；不自动切换 | 需要人工停旧/改 `--root` |
| 空间替换保留 rollback、无自动合并 | `.rollback-*` + `import-intent`；readers 重置 | 没有自动合并/回灌 |
| 恢复自动模型任务暂停 | settings false；queued/running failed；receipts 清空 | 已完成任务仍是旧状态，需复核 |
| 归档有上限，不是流式数据库备份 | 512 MiB 未压缩；全内存；上传 1 GiB | 大库需文件系统快照 |
| 场景兼容群/频道/游戏房间 | 场景 `type` 自由；scope 只有 private/group | 频道/游戏房间用 group 承载 |
| 条目增查改/撤回/恢复保留历史 | 已实现；history/tombstone | 已验证显式恢复、派生项保持撤回与重启持久化；完整 UI 恢复流程未覆盖 |
| 跨渠道逐条 shareable，证据/历史不外带 | query 过滤证据/history；recall 只在同 scope 给 sourceRefs | 显式 sceneId 可能读到其他 scene 的 shareable 条目 |
| 自动日常注入只当前场景 | 无 sceneId 按 bindings 过滤 | 显式 sceneId 语义更宽 |
| 跨渠道候选/管理员确认/原话支持升级 | `entry` 候选 + admin confirm + `support` | 需管理员或目标场景原话 |
| 冲突说法并存 | 场景不同文本并存；主体 possibleConflict | 人物事实槽 evidence-max 不保证全部并列 |
| 旧 group-memory 显式导入、保留未核验 | legacy:true/legacyRecord/confirm:false；旧 hits 不进可信度 | 导入工具默认 8091 |
| 重复/证据去重/墓碑 | 已实现 | 签名去重是文本规范化，不是语义去重 |
| 人物人工覆盖不被机器重写 | 投影优先；source_changed 标记 | 底层机器槽仍更新，不是阻止写 |
| derivedFrom 预览联动撤回；共用证据仅待核对 | proven/suspected；只撤 proven | 历史缺失依赖无法还原 |
| 人物→场景 durable intent，不宣称原子 | correction-intents + recover | 非 2PC；崩溃窗口 |
| 歧义昵称中性替换；稳定 ID 独立 | normalizer v3 | 历史误归属未全修复 |
| 旧向量兼容性检查，不自动重建 | encoding identity + MISMATCH | 不自动修文本/不自动花费 |
| 账号绑定读时投影、不放大权限、受场合限制 | link/accounts；scope 过滤 | 任意场合不自动互通 |
| UI trait 小卡前置/场景/绑定/备份预览 | 已实现 | 单页管理员界面，无多用户/审计 |
| 未知来源二次搬运仍 unknown | carryIdentity + 测试 | 显式 allowUnknown 才放行，仍标 unknown |
| 6 条合成 hard 改善 | before/after JSON | 微型合成，不外推生产 |
| 降级原因可诊断 | HTTP 返回按来源空间汇总的 `actualMode` 和 `degraded` | 不把降级结果伪装成向量检索 |

## 5. 升级步骤

### 5.1 先备份、再停服务

1. 先读 [备份与恢复操作说明](operations/backup-restore.md)。
2. 做一次完整服务备份（加密，密码 ≥8），下载到其他磁盘。
3. 对重点空间再做空间备份（便于单空间回滚/导入）。
4. 记录当前版本、根目录、端口、管理员 token 的保管位置（不要把 token 写进文档）。
5. 正常停止服务；确认 `.service.lock` 对应进程已退出。

### 5.2 更新代码并做静态检查

```powershell
node --check tools/standalone-server.mjs
node --check tools/standalone-backup.mjs
node --check tools/import-group-memory.mjs
node --check tools/evaluate-memory.mjs
node --check src/standalone/service.mjs
node --check src/standalone/worker.mjs
```

如果使用依赖，先按仓库说明安装；本次没有新增 Python 依赖，也没有 MCP 服务。

### 5.3 启动并验证

```powershell
node tools/standalone-server.mjs serve --root E:\vec-memory-data --host 127.0.0.1 --port 8091
```

验证：

- `GET /health`：`{status:"ok"}`；
- `GET /api/v1/version` 带 Bearer：版本/能力；
- 管理页能登录、看到 spaces/projects；
- 抽一个空间做 `status`/`recall`；
- 检查自动任务开关仍为 false。

### 5.4 normalizer v3 兼容性

升级后旧向量不一定可用：

- 编码身份包含 `normalizer`；旧库没有记录或版本不同时，查询/写入可能报 `ENCODING_MISMATCH`。
- 服务不会自动重建，也不会自动为旧文本重新归属。
- 处理顺序：
  1. 先备份；
  2. 在副本上显式提交 `index` 任务，观察 `rebuild-job.json`；
  3. 确认新代完整、`vector-active.json` 指向正确代后，再用于生产；
  4. 如果配额/端点中断，任务可续跑；旧代在重建期间仍可服务；
  5. 不要为了“看起来正常”手工改 `vector-active.json`。
- 旧文本误归属（例如撞名）不会因为重建自动变对；重建只解决编码/索引，不解决历史语义。

### 5.5 旧 group-memory 导入

- 用 `tools/import-group-memory.mjs` 显式导入；工具会保留 `legacyRecord`/`legacy:true`，条目标记为未核验候选。
- 旧 `hits` 不参与新场景条目的可信度。
- 导入后要人工核对；不要把“导入成功”当“内容正确”。
- `tools/import-group-memory.mjs` 默认 URL 为 `http://127.0.0.1:8091`，可用 `VEC_MEMORY_URL` 覆盖；管理凭据用 `VEC_MEMORY_ADMIN_TOKEN`。

### 5.6 账号绑定

- 只有管理员能绑定/解绑；两个账号必须先登记。
- 绑定是读时投影，不改原账号；不会扩大空间权限；人物读取仍受当前场合限制。
- 升级后不要批量自动绑定；逐对确认，保留解绑能力。

### 5.7 备份/恢复演练

至少做一次：

- 完整备份 → `inspect` → 旁置恢复 → `audit` → 临时端口启动；
- 空间备份 → 导入新空间 → 检查 readers/绑定/场景/receipts；
- 显式替换 → 确认 `.rollback-*`、readers 重置、账号绑定保留；
- 错密码/损坏归档 → 确认拒绝且不切换。

## 6. 回退

1. 先按 [备份与恢复操作说明](operations/backup-restore.md) 第 9 节导出切换后新增写入；不要只切回旧目录。
2. 保留新根、导出目录、`.rollback-*`。
3. 旧版本不能读新协议状态时，不要覆盖；按旧版本入口重录/回灌，保留导出作为证据。
4. 回退后重新核对消息、事实、人工修订、场景、账号绑定、来源。
5. 没有自动合并工具；不要假设“切回旧目录就完整”。

## 8. 已知问题/欠账

- 包、适配器和发布版本统一为 `0.32.0`；服务版本读取 `package.json`，避免独立常量漂移。
- QQ 适配层默认 8088、文件头 0.32.0；接入新服务时须显式配置 8091。
- `tools/import-group-memory.mjs` 默认 URL 为 `http://127.0.0.1:8091`，可用 `VEC_MEMORY_URL` 覆盖；管理凭据用 `VEC_MEMORY_ADMIN_TOKEN`。
- 场景显式恢复及重启持久化已有测试；完整管理页全按钮交互仍未覆盖。
- 完整恢复需要人工切换；没有自动切换。
- 空间替换不自动合并、不自动恢复 readers。
- 跨文件无 2PC；人物→场景用 intent 恢复，不是原子提交。
- 备份 512 MiB 上限、全内存。
- 消息明文落盘；模型调用可能出境；空间备份可未加密。
- 无内置 TLS/限速/token 轮换/审计日志。
- 不是 MCP；不要按 MCP server 接入。

## 9. 一句话

0.32.0 让服务的认证、场景、人工纠正、备份恢复和降级边界更清楚；它仍然是个人自托管工具，按单机、单写者、可停写、人工验收的边界使用。
