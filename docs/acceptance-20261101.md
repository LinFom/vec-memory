## 用什么设计解决什么问题

| 问题 | 本次采用的设计 | 代价与边界 |
|---|---|---|
| 错误印象反复生成、需要清空整个档案 | 条目修订历史、原证据去重、已纠正签名墓碑、人工覆盖优先 | 精确规范化去重；不同措辞不宣称语义等同 |
| 人物与群印象纠正不同步 | derivedFrom 明确依赖图、预览令牌、持久纠正意图与重启重放 | 仅明确依赖联动；共用证据列为疑似，不自动删；旧数据缺失依赖无法凭空还原 |
| 相近昵称串人 | 稳定账号 ID；歧义昵称中性归一化；normalizer v3 编码检查 | 不自动修复历史误归属、不自动付费重建向量 |
| 游戏玩家与 QQ 成员对应不上 | 管理员确认的可撤销账号关联，读取时汇总，不改原始证据归属 | 管理页可显式跨场合总览，项目召回仍遵循原场合权限 |
| 群记忆不能跨渠道管理 | 通用场景档案 CRUD；跨渠道逐条 shareable；外部补充候选；目标场景证据/人工确认升级 | 摘要共享不自动开放原话或历史；旧群档案显式导入并标未核验 |
| 无法可靠恢复 | 停写一致备份、AES-GCM/scrypt、哈希清单、旁置审核、空间安装意图、回退副本 | 完整恢复需手工切换启动根；512 MiB 内容上限，使用内存 |
| 无关记忆仍被注入 | 有查询时语义候选采用 hard 阈值；HTTP 报告真实降级原因 | 六例合成评估不能证明真实抽取质量或长期优势 |
| 稳定档案被长印象淹没 | 人物 trait 小卡前置，动态印象置后，保留每项来源 | 已验证读取布局，未覆盖管理页所有按钮 |

保留 Node.js 和既有存储/记忆算法，按场景状态、备份恢复和纠正恢复边界拆出模块。没有证据表明换语言会解决身份、来源或事务问题，因此没有重写 Python。

## 部署边界

本次更新了独立项目和本机 QQ 插件源码。没有自动切换生产服务配置，没有对真实 QQ 群发消息，没有运行付费模型批处理或改写历史身份归属。生产升级请先按 [备份恢复说明](operations/backup-restore.md) 备份、旁置验证，再按照 [升级说明](upgrades-20261101.md) 切换；停用旧群记忆采集/注入，避免新旧两套并行写入。

完整设计见 [完整设计文档](完整设计文档.md)，不足与取舍见 [项目客观评估](项目客观评估.md)。
