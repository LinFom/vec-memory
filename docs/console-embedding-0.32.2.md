# 0.32.2：QQ 控制台内嵌与本机启动

QQ 的“记忆库”页直接嵌入独立管理页，管理凭据仍在服务页面中输入，不从适配器转交项目凭据。独立服务默认禁止嵌入；只有明确配置的 HTTP(S) 来源可以嵌入。允许来源的 `/health` 探测支持 CORS，业务 API 仍要求凭据和同源写入。

手工启动时可重复传 `--embed-origin http://127.0.0.1:3210` 和 `--embed-origin http://127.0.0.1:3211`。不得填路径、凭据或通配符。CLI 与 QQ 适配层使用相同的服务入口。

本机自动启动需配置 `autoStartService:true`、程序目录 `serviceRoot`、已初始化的数据目录 `serviceDataRoot`，以及 `managementOrigins` 来源数组。仅启动明确指定的现有本机 HTTP 服务，不初始化新目录；远程服务由其部署端管理。适配器每次同步前检查服务，启动尝试每进程最多每分钟一次，两个 QQ 实例仍由服务的数据目录锁避免重复写入。自动启动不依赖 Windows 登录启动目录。

新增模块 `service-start.mjs` 必须随 QQ 适配器一起安装。旧协议仍使用原实例启动器和 `/manage.html`。已打开的 QQ 界面可能缓存旧模块，更新后刷新界面重新加载。

验收覆盖真实服务启动、来源白名单、默认禁止嵌入、健康探测 CORS、管理凭据/同源边界；另以真实 Electron 渲染器验证内嵌管理页登录、场景区显示和跨来源凭据隔离。测试使用临时库，不调用模型。
